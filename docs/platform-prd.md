# Web 端个人开发平台：PRD

> 已确认版说明（2026-10-26）：技术栈已改为 Node TS + Express + Vue 前后端分离、UI 方向 A 实验室工作台；旧的零依赖原生实现已删除，本文件功能范围不变，技术细节以 platform-architecture.md / platform-detailed-design.md 为准。

- 版本：v0.1
- 用户：li 一人。
- 仓库：https://github.com/joesaas/personal-dev-platform
- 应用：`apps/web-platform/`（包名 `@platform/web-platform`）
- 文档位置：本工程 `docs/`，本文件与原型、架构、详细设计、实现、部署文档同目录。

## 1. 背景与目标
li 已有 Google monorepo 单仓骨架，但缺一个“打开就能测”的地方：测一段代码、测一次模型调用、看一个开源项目，都要先建项目或开终端。目标是把这三件事收进一个带登录的网页工作台，先跑通，再扩展。

## 2. 非目标
- 不是公开产品，不做注册、多租户、付费、分享链接。
- 不是通用在线 IDE，不做文件系统、终端、多语言执行。
- 不是代码托管或 CI 平台，不替代 GitHub Actions（CI 文件因 App 无 Workflows 权限仍只在本地，见实现文档）。

## 3. 功能需求

### 3.1 登录（P0）
- FR-1：未登录访问 `/api/*`（除登录接口外）返回 401，前端跳转登录页。
- FR-2：登录接口接受用户名 + 密码，成功后发 HttpOnly 会话 Cookie，失败不区分用户名错还是密码错。
- FR-3：退出接口清除会话，前端回到登录页。
- FR-4：口令来自环境变量 `DEV_PLATFORM_PASSWORD`；未设置时服务器启动打印一次随机口令，仅当次有效。
- 安全说明：本登录只适用于个人本地或自有服务器内网使用，不适用于公开互联网；公开部署前必须换成 OAuth 或反向代理鉴权，见部署文档。

### 3.2 代码实验室（P0）
- FR-5：输入 JS 代码，点击运行，返回 `console.log` 输出或错误信息。
- FR-6：单次执行超时 2 秒，超时返回超时错误，不阻塞其他请求。
- FR-7：沙箱内不提供 `require`、`process`、文件、网络能力；超出沙箱能力的代码应报错，而不是静默放行。
- FR-8：默认示例代码可一键运行，验证链路。

### 3.3 OpenRouter Guardrails 实验室（P0）
- FR-9：前端表单：API Key、模型、系统提示、用户提示、禁词、输入/输出禁止模式、最长字数、是否要求 JSON 输出。
- FR-10：发送前做输入 Guardrails，不通过则拦截并标明规则，不发请求。
- FR-11：收到模型输出后做输出 Guardrails，逐条显示通过/失败，不只给总结果。
- FR-12：API Key 只存浏览器 localStorage，不发给本平台服务器、不写数据库、不进仓库。
- 重要澄清：本实验室实现的是“围绕 OpenRouter 调用的 Guardrails 检查”，不是已核实的 OpenRouter 官方 Guardrails 产品接口；文档和界面里不得把它写成官方产品。用户如需官方产品能力，须另行提供官方接口文档后再接。

### 3.4 GitHub Demo 实验室（P0）
- FR-13：输入 `owner/repo` 或完整链接，解析失败要提示正确格式。
- FR-14：返回仓库基本信息：全名、描述、星数、语言、默认分支、公开与否。
- FR-15：返回 README 摘要，并据此展示 clone 命令与体验清单（只展示，不执行）。
- FR-16：仓库不存在或 GitHub API 限流时，提示具体原因，不给空结果。

### 3.5 文档与工程（P0）
- FR-17：原型、PRD、架构、详细设计、实现、部署六份文档全部在 `docs/` 下，互相引用时用相对路径和文件名，不另起文档站。
- FR-18：新应用遵循 monorepo 约定：应用进 `apps/`、共享进 `packages/`、根目录 `npm run build` 与 `npm test` 能覆盖它。
- FR-19：以后凡改 `.github/workflows/` 的推送必须把该文件排除在 App 推送清单外（App 无 Workflows 权限，见实现文档），否则整包 403。

## 4. 非功能需求
- NFR-1：零外部运行时依赖：服务器只用 Node 标准库 + TypeScript 编译产物，不引入 Express、数据库、Redis。
- NFR-2：本地启动后 10 秒内可打开登录页；登录后三个实验室均可直接使用，无需额外配置（OpenRouter 实验室除外，需要用户自己的 Key）。
- NFR-3：接口错误一律返回 `{ ok: false, error: "<可读原因>" }`，不泄露堆栈和会话信息。
- NFR-4：前端在小屏下导航可折叠、表单可单列，不要求桌面端像素级还原。

## 5. 验收标准（模板默认）
产出物可直接打开或运行，关键结果有可复核的证据（测试输出、哈希、链接），不是只报一句完成。本版本的具体复核点在实现文档第 5 节：本地构建通过、单元测试通过、登录/代码运行/GitHub 查询三条冒烟链路有真实输出。
