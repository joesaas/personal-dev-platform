# Web 端个人开发平台：需求原型

- 适用：li 自己用，只给一个人用，不做多租户。
- 底座：现有 monorepo（npm workspaces + TypeScript，apps / packages / tools / infra），新应用进 `apps/web-platform/`，共享代码进 `packages/`。
- 状态：v0.1 原型已实现，见 `docs/platform-implementation.md`。

## 一句话
一个带登录的网页工作台：打开就能快速测一段代码、测一次带 Guardrails 的 OpenRouter 调用、快速看一个 GitHub 开源项目能不能跑起来。

## 用户与场景
- 唯一用户：li。
- 场景 A：手头有一段 JS，想立刻看输出，不想新建项目、装依赖、开终端。
- 场景 B：想试 OpenRouter 的某个模型，先过一遍 Guardrails（输入禁词、输出格式、长度、敏感模式），再决定要不要进正式代码。
- 场景 C：看到一个 GitHub 开源项目，先看它是什么、README 说什么、怎么跑，再决定要不要 clone。

## 页面结构（v0.1）
```
顶栏：个人开发平台 | 当前登录用户 | 退出
左侧导航（三个实验室，不是三个相同卡片）：
  代码实验室
  OpenRouter Guardrails 实验室
  GitHub Demo 实验室
主区按实验室切换，互不干扰。
```

### 1. 登录页
- 只有用户名 + 密码两个框，错了只说“用户名或密码不对”，不提示是哪一项错。
- 登录成功进工作台，未登录直接打开任何实验室接口都返回 401。
- 口令来源：环境变量 `DEV_PLATFORM_PASSWORD`；本地未设置时，服务器启动时在控制台打印一次随机口令，仅当次运行有效，见部署文档。

### 2. 代码实验室
- 左：代码编辑框（默认一段示例，输出 Hello）。
- 右：运行结果区，分“输出”和“错误”两栏。
- 按钮：运行。超时 2 秒即停，不阻塞服务器。
- 安全边界：只在 Node `vm` 沙箱里跑纯 JS，不给 `require`、`process`、文件和网络能力；跑任意不可信代码、跑 Python、跑系统命令都不在 v0.1 范围内。

### 3. OpenRouter Guardrails 实验室
- 输入：API Key（只存在浏览器 localStorage，不发给本平台服务器、不入库）、模型名（默认 `openai/gpt-4o-mini`，可改）、系统提示、用户提示。
- Guardrails（本平台实现的检查，不是官方 OpenRouter Guardrails 产品，见 PRD 说明）：
  - 输入检查：禁词表（逗号分隔）、禁止模式（正则，可选）。
  - 输出检查：最长字数、必须为 JSON（可选）、禁止模式（正则，可选）。
  - 检查不通过时直接拦截，不发 OpenRouter 请求，并在结果区标明是哪条规则拦的。
  - 检查通过后由浏览器直接调用 `https://openrouter.ai/api/v1/chat/completions`，结果区同时显示模型原文和每条规则的通过/失败。
- 失败态要说清：Key 不对、模型不存在、网络失败、规则拦截，各自有不同提示，不混成一句“失败了”。

### 4. GitHub Demo 实验室
- 输入：`owner/repo` 或完整 GitHub 仓库链接。
- 输出：仓库名、描述、星数、语言、默认分支、README 前段摘要。
- 输出：按 README 推导的“快速体验清单”：clone 命令、README 里提到的安装/运行命令（只展示，不自动执行）。
- 边界：v0.1 不自动 clone、不自动安装依赖、不自动运行陌生仓库的代码；自动运行陌生代码是安全风险，留作后续沙箱阶段。

## 设计方向（按 frontend-design-muse）
- 定调：实验室工作台，不是营销页，没有 hero 大图。
- 颜色：底色浅钢灰 `#EEF1F5`、面白、墨色 `#1B2A3A`、主色深青 `#0F766E`、通过绿、拦截红、警告琥珀；不用奶油 + 陶土、不做全黑 + 荧光绿、不做千篇一律的 SaaS 圆角卡片阵。
- 字体：正文系统 sans，代码与输出用等宽（ui-monospace），标题与正文不靠单字变色抢眼。
- 布局：左侧导航 + 主工作区，代码实验室左右分栏，Guardrails 实验室表单在左、结果在右，GitHub 实验室先看仓库信息、再看体验清单。
- 交互：按钮文案就是动作本身（运行、发送、获取仓库信息、退出）；空状态给下一步动作，不只说“暂无数据”。

## 不在 v0.1 里做的事
- 多用户、注册、找回密码、第三方 OAuth。
- 在服务器上执行 Python、Shell、任意仓库代码。
- 把 OpenRouter Key 存到服务器或数据库。
- 公开部署、自定义域名、HTTPS 证书（部署文档只写本地与自有服务器两种路径，见部署文档）。
